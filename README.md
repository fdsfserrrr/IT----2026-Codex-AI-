Harness Engineering——为AI构建可靠的工程执行系统
当AI开始承担越来越多的编码工作，一个更根本的问题浮出水面：如何确保AI产出的代码是可靠的？行动营第二阶段V1的设计正是围绕这一命题展开——用Harness建立可量化的质量门禁，而非依赖人肉审查和主观判断。

Harness Engineering是2026年AI工程领域最重要的范式创新。Martin Fowler在2026年2月专门撰文提出这一术语，其核心定义为：Agent = Model + Harness。Harness是所有不属于模型本身的代码、配置和执行逻辑，包括系统提示词、工具执行层、基础设施、编排逻辑以及确定性执行的钩子与中间件。用一个计算机类比来理解：模型是CPU，上下文窗口是内存，Harness是操作系统，Agent则是运行在操作系统之上的应用程序。

这一范式并非理论空谈。OpenAI的Codex团队用这套方法生成了超过一百万行生产代码，全程零手动输入，三名工程师驱动Codex完成了约1500个Pull Request，平均每人每天处理3.5个PR。团队的核心理念是：人类掌舵，智能体执行。工程师的主要任务从编写代码转为设计环境、明确意图和构建反馈回路。

行动营在V1阶段引入的质量门禁体系，正是Harness工程的核心落地。其关键设计包括：修改后触发快速门禁（Lint、类型检查、关联单测），任务完成前执行集成与回归测试，PR阶段由CI进行全量验证。质量门禁的本质是把验证从“软约束”变成“硬门控”——AI不能在没有通过验证的情况下声称任务完成。

到了V2阶段，课程进一步讨论多Agent协作的编排问题：谁负责拆任务、谁负责执行、谁负责检查、什么时候需要人工介入。如果这些事情没有被设计清楚，Agent越多，系统反而越容易失控。这正是Harness Engineering从单Agent执行扩展到多Agent编排的技术跃迁。
